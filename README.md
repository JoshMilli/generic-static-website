# Basecamp Chat Webhook + Analytics

This project includes a small Node.js server that exposes a webhook endpoint for Basecamp chat events, stores them locally for analysis, and provides a lightweight analytics dashboard.

## What you get

- POST /webhooks/basecamp — payload URL to register as a Basecamp webhook
- GET /analytics.json — aggregated analytics (JSON)
- GET /analytics — simple dashboard with charts
- GET /healthz — basic health check
- Optional: automatic free public URL using Localtunnel (no account needed)

Events are appended to data/events.jsonl as JSON Lines (raw payload + normalized fields).

## Run locally (free + public URL)

1. Install dependencies:

   npm install

2. Start the server with an automatic free tunnel:

   npm run dev:tunnel

3. The server will print a line like:

   Public Payload URL (via localtunnel): https://abc123.loca.lt/webhooks/basecamp

   You can also fetch it at:
   http://localhost:3000/_tunnel
   And it’s written to:
   data/tunnel_url.txt

4. View analytics:

   http://localhost:3000/analytics

If you prefer not to use Localtunnel, you can run without it:

   npm run dev

Then create your own tunnel (e.g., ngrok http 3000) and use the URL + /webhooks/basecamp.

## Register the webhook in Basecamp

In Basecamp’s “Add a new webhook” screen:
- Payload URL: the Localtunnel URL printed by the server (ends with /webhooks/basecamp)
- Content types: select “Message” and “Client reply” (and any others you want)
- Enable the webhook

We store the full payload plus normalized fields (sender, message text, timestamps) for later analysis.

## Deploy (optional)

For a persistent hosted URL, deploy on a free plan at Render, Railway, Fly.io, etc. (you’ll need an account on those platforms).

- Command: npm start
- Expose port 3000 (or rely on platform PORT)
- After deploy, use https://YOUR_DOMAIN/webhooks/basecamp as your Basecamp Payload URL

## Notes

- Basecamp does not document a signed webhook scheme. If you want to restrict access, consider a shared secret in the path or header, or an allowlist at your gateway.
- The summarization is intentionally simple to keep dependencies light. Swap in an LLM or a more advanced pipeline if needed.
